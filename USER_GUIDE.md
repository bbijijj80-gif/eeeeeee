# Руководство пользователя MiniDB

Это подробная инструкция для тех, кто просто хочет **использовать** программу
MiniDB — запускать её, работать с базой данных, переносить её на флешку и
понимать, что лежит в файлах `minidb.db` и `minidb.wal`. Если вам нужна
инструкция по сборке программы из исходного кода — смотрите `README.md`.

## 1. Что такое MiniDB и какие файлы она создаёт

MiniDB — это программа для хранения и обработки данных с помощью языка SQL
(как упрощённая версия MySQL/PostgreSQL/SQLite). При каждом запуске в той же
папке, где лежит `minidb.exe`, программа создаёт (или открывает, если они уже
есть) два файла:

| Файл          | Что в нём хранится                                                                 | Формат                         |
|---------------|-------------------------------------------------------------------------------------|---------------------------------|
| `minidb.db`   | Сами данные: все таблицы, строки, индексы. Это "тело" вашей базы данных.            | Двоичный (не открывать в блокноте) |
| `minidb.wal`  | Журнал операций (Write-Ahead Log) — список всех выполненных команд для восстановления после сбоя. | Обычный текстовый файл          |

**Важно:** оба файла нужны вместе. Если вы переносите базу данных на флешку
или на другой компьютер — копируйте **оба файла**, а не только `minidb.db`.

Пока эти два файла лежат рядом с `minidb.exe` (или в рабочей папке, из которой
вы запустили программу), все ваши таблицы и данные сохраняются между запусками.

## 2. Первый запуск

1. Дважды щёлкните `minidb.exe` (или, если у вас есть только исходный код,
   сначала соберите проект — см. `README.md`, раздел "Установка и сборка").
2. Откроется окно с приглашением `minidb>` — программа готова принимать
   команды на языке SQL.
3. Каждую команду нужно набирать **в одну строку** и нажимать Enter.
4. Чтобы выйти из программы, наберите `exit` или `quit`.

Пример сессии:

```
minidb> CREATE TABLE users (id INT, name VARCHAR(50))
✓ Таблица 'users' успешно создана
minidb> INSERT INTO users VALUES (1, 'Alice')
✓ 1 строка добавлена в таблицу 'users'
minidb> SELECT * FROM users
┌────┬───────┐
│ id │ name  │
├────┼───────┤
│ 1  │ Alice │
└────┴───────┘
✓ 1 строк(и) найдено (поиск по B+ дереву)
minidb> exit
```

## 3. Полный список команд SQL

### 3.1. Создание таблицы — `CREATE TABLE`

```sql
CREATE TABLE название_таблицы (столбец1 ТИП, столбец2 ТИП, ...)
```

Поддерживаемые типы столбцов:

- `INT` или `INTEGER` — целое число;
- `VARCHAR(N)` или `TEXT` — текстовая строка (число `N` можно указывать, но
  оно не проверяется — это просто подсказка для читаемости схемы).

Пример:

```sql
CREATE TABLE products (id INT, name VARCHAR(100), price INT)
```

**Совет:** если первый столбец таблицы — `INT`, MiniDB автоматически создаёт
по нему быстрый индекс (B+ дерево). Поэтому первым столбцом удобно делать
что-то вроде `id` — уникальный числовой идентификатор строки.

### 3.2. Добавление строки — `INSERT INTO`

```sql
INSERT INTO название_таблицы VALUES (значение1, значение2, ...)
```

Числа пишутся без кавычек, текст — в одинарных кавычках `'...'`.

Пример:

```sql
INSERT INTO products VALUES (1, 'Клавиатура', 1500)
INSERT INTO products VALUES (2, 'Мышь', 500)
```

Значения нужно перечислять **в том же порядке**, в каком столбцы были
указаны при создании таблицы.

### 3.3. Выборка данных — `SELECT`

```sql
SELECT * FROM название_таблицы
SELECT столбец1, столбец2 FROM название_таблицы
SELECT * FROM название_таблицы WHERE столбец = значение
```

Поддерживаемые операторы сравнения в `WHERE`: `=`, `<>`, `<`, `>`, `<=`, `>=`.

Примеры:

```sql
SELECT * FROM products
SELECT name, price FROM products WHERE price > 1000
SELECT * FROM products WHERE id = 2
```

Если условие в `WHERE` — точное совпадение (`=`) по первому (индексированному)
столбцу, MiniDB найдёт строку почти мгновенно через B+ дерево, а не будет
перебирать всю таблицу — в конце вывода вы увидите пометку
"поиск по B+ дереву" вместо "полное сканирование".

### 3.4. Выход из программы

```
exit
```
или
```
quit
```

## 4. Как перенести базу данных на флешку

Есть два способа пользоваться MiniDB с флешки.

### Способ А — программа на компьютере, база данных на флешке

1. Скопируйте оба файла — `minidb.db` и `minidb.wal` — с компьютера на флешку
   (например, в папку `E:\МояБаза\`).
2. Чтобы MiniDB работала именно с этими файлами, нужно запускать `minidb.exe`
   так, чтобы **рабочей папкой** была папка на флешке. Проще всего:
   - откройте папку на флешке в проводнике Windows;
   - скопируйте туда же `minidb.exe` (или создайте на неё ярлык);
   - запускайте `minidb.exe` именно из этой папки на флешке.

При таком запуске программа создаст/откроет `minidb.db` и `minidb.wal` рядом
с собой — то есть прямо на флешке.

### Способ Б — вся программа целиком на флешке

Скопируйте на флешку весь собранный проект — `minidb.exe` вместе с файлами
`minidb.db`/`minidb.wal` (если они уже есть). Тогда флешку можно вставить в
любой Windows-компьютер и запускать программу прямо с неё, без установки.

**Важно:** MiniDB не требует установки и не пишет ничего в реестр Windows —
это обычный `.exe`-файл, который можно свободно копировать и запускать из
любой папки, в том числе с флешки.

## 5. Как отформатировать флешку под MiniDB

MiniDB не требует какой-то особой файловой системы — она просто создаёт два
обычных файла на диске. Но важно выбрать формат флешки правильно, иначе база
данных может однажды "не поместиться" или вообще не создаться.

### Почему это важно

Файловая система **FAT32** (самая частая на старых флешках "из коробки") не
умеет хранить файлы больше **4 ГБ**. Если ваша база данных вырастет больше
этого размера, Windows откажется писать в `minidb.db`, и вы получите ошибку
записи. Поэтому для MiniDB рекомендуется формат **exFAT** или **NTFS**, где
такого ограничения нет.

### Как отформатировать флешку в exFAT (рекомендуется)

exFAT — лучший выбор для флешки: не имеет ограничения FAT32 по размеру файла,
и, в отличие от NTFS, нормально читается/пишется и на Windows, и на macOS,
и на большинстве современных прошивок телевизоров/консолей.

1. Вставьте флешку в компьютер.
2. **Обязательно скопируйте с флешки всё, что вам нужно** — форматирование
   удалит все данные на ней без возможности восстановления.
3. Откройте "Проводник" (клавиша Win + E).
4. Найдите флешку в списке дисков (обычно `D:`, `E:` или другая буква),
   щёлкните по ней **правой кнопкой мыши** и выберите **"Формат..."**
   (англ. "Format...").
5. В открывшемся окне:
   - **Файловая система** — выберите `exFAT`;
   - **Размер кластера** — оставьте "По умолчанию" (Default allocation size);
   - **Метка тома** — можете вписать любое имя, например `MiniDB`;
   - галочку **"Быстрое форматирование"** можно оставить включённой — для
     обычной флешки этого достаточно.
6. Нажмите **"Начать"**, подтвердите предупреждение об удалении данных и
   подождите завершения (обычно — секунды).
7. Готово: скопируйте на отформатированную флешку `minidb.exe` (и, если есть,
   `minidb.db`/`minidb.wal`) — как описано в разделе 4.

### Как отформатировать флешку через командную строку (альтернативный способ)

Если контекстное меню недоступно, можно сделать то же самое через команду
`format` в командной строке (запущенной **от имени администратора**):

```bat
format X: /FS:exFAT /Q /V:MiniDB
```

Замените `X:` на реальную букву вашей флешки (посмотреть букву можно в
"Этот компьютер"). Флаг `/Q` — быстрое форматирование, `/V:MiniDB` — метка
тома. **Дважды проверьте букву диска перед нажатием Enter** — форматирование
неправильного диска уничтожит данные на нём безвозвратно.

### А что насчёт NTFS?

NTFS тоже подходит и снимает ограничение в 4 ГБ, но у неё есть нюанс: если
вы будете переставлять флешку между Windows и macOS/Linux, чтение будет
работать, а вот запись с "не-Windows" систем может требовать дополнительных
драйверов. Если флешка будет использоваться только с Windows — NTFS тоже
хороший выбор, шаги форматирования те же, просто в шаге 5 выберите `NTFS`
вместо `exFAT`.

## 6. Как прочитать файлы базы данных вручную

- **`minidb.wal`** — обычный текстовый файл. Его можно открыть блокнотом,
  Notepad++ или любым текстовым редактором. Каждая строка — одна записанная
  операция в формате `LSN|ID_транзакции|ТИП|данные`, например:
  ```
  0|0|BEGIN|
  1|0|COMMIT|
  ```
  Это внутренний журнал восстановления, не предназначенный для
  редактирования руками, но его удобно посмотреть, чтобы понять, что делала
  программа.

- **`minidb.db`** — двоичный файл (набор страниц по 4096 байт со служебными
  заголовками, деревьями и сырыми байтами строк). Открывать его в блокноте
  **не нужно** — вы увидите нечитаемые символы. Прочитать содержимое базы
  данных можно только через саму программу MiniDB, командой `SELECT`.

Если вам нужно "посмотреть, что внутри" — правильный способ — запустить
`minidb.exe` в той же папке, где лежит `minidb.db`, и выполнить
`SELECT * FROM название_таблицы`.

## 7. Резервное копирование и перенос на другой компьютер

Чтобы сделать резервную копию базы данных:

1. Закройте `minidb.exe` (наберите `exit`), чтобы файлы точно не использовались.
2. Скопируйте `minidb.db` и `minidb.wal` в надёжное место (другую папку,
   флешку, облако).

Чтобы восстановить базу данных из копии или перенести её на другой компьютер:

1. Скопируйте оба файла в папку, где лежит `minidb.exe` на новом компьютере
   (или в ту же папку, если восстанавливаете после проблемы).
2. Запустите `minidb.exe` — программа откроет перенесённые данные как ни в
   чём не бывало.

## 8. Частые проблемы и их решение

**Кириллица отображается «иероглифами».**
Обновите программу до последней версии — начиная с текущей сборки MiniDB
сама переключает консоль Windows в кодировку UTF-8 при старте. Если
проблема осталась, попробуйте вручную выполнить в командной строке перед
запуском: `chcp 65001`.

**При запуске `minidb.exe` пишет "не удалось открыть файл БД".**
Обычно это означает, что программа не может писать в свою рабочую папку —
например, если вы запускаете её прямо из архива `.zip` без распаковки, или
с флешки, защищённой от записи (проверьте переключатель защиты на самой
флешке, если он есть). Распакуйте программу в обычную папку на диске или на
флешке без защиты от записи и запустите снова.

**База данных не помещается на флешку / ошибка записи при большом объёме данных.**
Скорее всего, флешка отформатирована в FAT32, который не поддерживает файлы
больше 4 ГБ. Отформатируйте её в exFAT — см. раздел 5.

**После переноса на другой компьютер таблицы пустые.**
Проверьте, что вы скопировали **оба** файла — `minidb.db` и `minidb.wal` —
и что `minidb.exe` запускается именно из той папки, где они лежат (программа
всегда создаёт/использует `minidb.db`/`minidb.wal` в своей текущей рабочей
папке, а не где-то в фиксированном месте).

**Проблемы со сборкой программы из исходного кода (ошибки CMake, "нмаке",
кодировка в `build.bat` и т.п.).**
Это уже вопрос не использования, а сборки — см. `README.md`, раздел
"Установка и сборка".
